# 用例目录与产品隔离

- `common/`：跨产品公共诊断用例及其 `registry.json`。
- `g_series/`：G系列业务用例及其 `registry.json`。G1/G3/G6 功能相同，共用脚本，不再拆成三份。
- `conftest.py`：所有产品共用的设备和 Appium fixture。
- `registry.json`：产品名称到独立注册表的目录映射。

工作台可选 Nova、G1/G3/G6、G7、G5；可把多副眼镜加入设备队列，复用同一手机并按已选 Sheet 的顺序运行。内部产品名 `G系列` 在界面显示为 `G1/G3/G6`，既有配置和用例编号保持不变。G7 暂时复用不限制型号的 G 系列脚本，并新增 9 条 G7 专属用例；实际通过仍取决于对应眼镜和 APP 版本的实机断言。Nova、G5 尚未接入业务用例。

新增其他产品的自动化时，建立独立目录（例如 `nova/`），新增该目录的 `registry.json`，并在根映射的 `products` 中加入产品配置名称和相对注册表路径。当前只创建已有实际用例的 G 系列目录。

每轮只加载公共注册表与当前产品注册表。不同产品可以使用相同的 Sheet 名及编号；同一产品与公共用例之间不得重复。产品条目只能引用自身目录下的脚本。公共驱动和可复用流程放在 studio，不通过跨产品导入测试文件复用。

用例适用范围写在注册表的 `models`（例如 `["G1", "G3"]`）或 `products` 标签中；不填写 `models` 表示适用于当前产品的所有已确认型号。执行器按当前选择过滤，不适用的用例记为“不适用”。自动化编号仍全局唯一并保持 `VisionRay_XXXX`，不通过编号区间推断眼镜型号。新型号的能力确认和实际用例实现后，再将其配置中的 `configured` 设为 `true`。

多型号队列复用同一份输入 Excel。使用者仅为本次勾选的 Sheet 指定队列中的一副眼镜；一个 Sheet 只交给一副眼镜，按工作簿 Sheet 顺序串行执行，相邻且使用同一设备的 Sheet 合并为一轮。每轮使用自己的型号、蓝牙名称和结果文件；批次报告按“型号 + 眼镜名称 + 用例编号”列出结果。不同型号的 Sheet 可以共用底层 APP 操作代码，但各自保留独立编号与证据。新增型号不能仅凭编号范围继承 G 系列脚本，应确认页面与能力差异。

G系列配对：PAIR_001(G1)、PAIR_002(G3)、PAIR_003(G6)，均调用 g_series/test_pairing.py::test_bind；由用户输入完整蓝牙名称识别型号并过滤。

G系列登录注册：`G00_登录注册` 的 A 列 `C-L_###` 映射到 B 列 `AUTH_###`，执行 `g_series/test_auth.py::test_auth[AUTH_###]`。当前实现56条，其余行保持未实现；不要用空测试占位。账号准备、注销后的重新注册与密码恢复见 `docs/登录注册自动化.md`。
