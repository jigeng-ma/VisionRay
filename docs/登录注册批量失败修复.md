# 登录注册批量执行修复

原轮次：`runs/20260916_180354_9ecc4f82`。56 条已实现用例最终为 6 通过、2 功能失败、48 执行异常；另40条未实现未执行脚本。

## 主要原因

1. `C-L_017` 本体执行通过，但注销后的强制注册清理未进入验证码页，账号留在未注册状态。
2. 后续用例没有重新核对服务端账号状态，直接以原密码登录。47条结果包含“登录后主页面”超时，实际界面是 `Not registered`。这是前置条件引起的连锁失败，不能据此认定47个功能都有缺陷。
3. 不依赖账号的页面检查也在清理阶段强制登录，因此本体正常仍被记为执行异常。
4. 登录页自动弹出的键盘遮住底部协议，`C-L_006` 在等待 `tv_privacy` 时超时。
5. `C-L_016` 转注册后邮箱为空，与表格“保留邮箱”预期不一致，属于保留的功能差异。

## 修改

- 执行前调用 `AuthPage.prepare()`，按用例要求准备账号。需要已注册时，检查标准密码实际可登录；未注册先注册，密码不同先通过邮箱恢复。需要未注册时先检查，账号存在才注销。
- 页面元素检查不强制创建账号。进入邮箱输入页后收起键盘；页面动作等待目标页面。
- 注册/注销后可以保留未注册状态，下一条自行准备。取消每条用例结束时无条件登录/注册，减少邮件配额消耗和状态依赖。改密仍恢复原密码并验证。
- 注册、找回、注销发送验证码后统一确认进入验证码页；明确的短时限流等待65秒后重试，最多3次。每日配额耗尽、无法确认发送结果、收信超时记录阻塞并保留原因。
- 前置条件失败在业务断言前记录阻塞，保存证据。没有修改实际结果不符合预期的业务断言。

单元检查覆盖未注册转注册、已注销不重复删除、已登录但密码变化的恢复、不依赖账号的清理、前置失败分类、其他账号保护及恢复失败不吞异常。
