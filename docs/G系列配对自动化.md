## 从窗口执行

1. 双击根目录 `启动测试工作台.cmd`，选择上述 Excel，仅勾选 `G01_配对`。
2. 选择手机。眼镜若未接 USB，选择“仅蓝牙连接（眼镜未接 USB）”。
3. 眼镜蓝牙完整名称由使用者填写，例如 `DPVR G1_13E6`。窗口自动识别产品“G系列”和型号 G1，型号栏只显示识别结果。以后更换设备时输入新设备的完整名称；不会用 USB 系统型号替代。
4. 确保 APP 已登录、未绑定任何设备，停在 Add Device 首页，眼镜已开机并可配对。不要同时手动操作手机。
5. 按需要勾选“配对后跳过引导”。不勾选时停在引导页；勾选时自动点击 Skip 和 Yes, skip it，验证目标眼镜首页。两条路径均持续处理配对弹窗。
6. 点击“启动 / 检查 Appium”，再开始执行。
7. 完成后查看本轮 `runs/<轮次>/report.html` 和 `results.xlsx`。

执行后眼镜保持绑定，手机停在所选的引导页或首页。再次执行前需要恢复未绑定状态。脚本不会清理 APP 数据、自动解绑其他设备或升级 APP/固件。

## 实际断言

- 未绑定首页存在 Add Device 入口。
- 点击后出现 Select Your Glasses。
- 根据型号完整名称查找卡片；在 `scrollContent` 内滚动，最多 12 次。每次重新定位，滚动到底后仍检查最后一屏。新增型号不依赖卡片序号或固定坐标。
- 选择型号后出现 Pairing Ready，点击 Next 后进入搜索状态或已经出现搜索结果。
- 只点击搜索列表中与本轮完整名称相同且唯一的设备。
- 绑定后必须进入 TutorialActivity，并同时存在 Explore Glasses 和 Begin；继续处理延迟配对弹窗，满足本轮系统配对要求后才通过。仅搜索到眼镜或仅跳转页面不判定完整配对通过。

眼镜搜索默认等待 45 秒，绑定等待 65 秒；定位失败保存页面 XML 和截图。未满足首页前提记“阻塞”，预期页面缺失或目标搜索超时记“失败”。

## 弹窗策略

`studio/popups.py` 统一处理，`configs/catalog.json` 的 `popup_rules` 集中维护签名和按钮。每次等待元素先检查弹窗，处理后重新定位，不重复整个绑定动作。

| 弹窗 | 默认策略 | 验证程度 |
|---|---|---|
| Bluetooth pairing request / 蓝牙配对请求 | 仅本轮已点击目标设备后，且弹窗包含完整目标名称，才点击 Pair/配对；名称不匹配则阻塞 | 中英文模拟测试通过；本轮英文系统弹窗实机捕获并自动点击 Pair |
| New Update | 同时匹配标题与 Update 按钮，点击唯一 Cancel | 基于用户截图配置，模拟测试通过；本轮未实机触发 |
| Firmware Update | 同时匹配标题与 Update Now，点击 tv_cancel | 本轮实机触发并成功取消 |
| 未知弹窗或未知权限请求 | 不盲点；等待超时保留截图和 XML，按实际 UI 补规则 | 不宣称能自动处理所有弹窗 |

同一等待阶段最多处理 6 次已知弹窗，反复出现则阻塞。若按钮不唯一或缺失，不尝试点击其他类似按钮。

升级用例需要验证更新弹窗时，可在调用任何等待操作之前设置：

```python
android.popups.preserve.add('firmware_update')
```

这会保留该弹窗给业务用例断言。APP 更新同理使用 `app_update`。

Android 厂商的系统按钮资源 ID 可能不同；当前 Pair 规则使用 `android:id/button1`，首次在其他手机触发时应核对 XML 后更新配置。

系统已保留配对关系时，重新绑定可能不弹 Pair。默认 `pairing.require_pairing_prompt: true`，必须实际确认目标配对弹窗，否则失败。进入引导页后继续监测最多 60 秒，不提前结束；若本轮明确不要求首次系统配对验证，可改为 false，但仍保留 30 秒观察窗口。`steps.jsonl` 记录实际确认次数。首次配对验收前应清除该目标的系统配对记录。

## 维护位置

- `configs/catalog.json`：页面定位、弹窗签名、G1/G3/G6 名称识别规则、入口文字和等待时间。三款共用功能能力与业务流程，型号仅覆盖配对入口及显示。
- `studio/pairing.py`：配对公共业务流程。
- `studio/android.py`：集中等待、点击、截图及日志。
- `studio/popups.py`：弹窗处理及目标设备身份检查。
- `cases/g_series/test_pairing.py`、`cases/g_series/registry.json`：用例与 Excel 编号映射。

只确认了 G 系列的配对能力，其他能力仍保持未知。配置列表按 common → product → model 覆盖，其中数组是整体替换；覆盖 popup_rules 时要保留仍需使用的规则。
